客户端/SDK

HugeGraph 官方多语言客户端 SDK（Java、Python、Go 等）概览与接入指引。
  • 1: HugeGraph Java Client
  • 2: HugeGraph Python 客户端快速上手
  • 3: HugeGraph Go 客户端快速入门

HugeGraph 提供多语言客户端 SDK，方便在不同语言与技术栈中连接 HugeGraph Server，进行 Schema 管理、顶点与边数据读写、Gremlin 遍历及高级分析。

支持的客户端

  • HugeGraph Java Client

    官方核心 Java SDK，提供与 Gremlin 语法相近的 API 风格，支持完整的 Schema 管理、CRUD、Gremlin 查询及 Traverser 算法，并支持 GraphSpace 隔离。

  • HugeGraph Python Client

    官方 Python SDK（pyhugegraph），位于 HugeGraph-AI 仓库，支持管理 Schema、读写图数据及提交 Gremlin 查询，深度集成 HugeGraph-LLM 与 HugeGraph-ML。

  • HugeGraph Go Client

    官方 Go SDK，支持版本查询、Schema 定义（PropertyKey/VertexLabel/EdgeLabel）、顶点操作与 Gremlin 查询。

选择建议

  • 生产级 Java/Scala 服务：推荐使用 HugeGraph Java Client，功能最完备，覆盖所有底层能力与连接池管理。
  • AI/LLM/算法与数据科学应用：推荐使用 HugeGraph Python Client（pyhugegraph），深度适配 HugeGraph-LLM、HugeGraph-ML 及 Python 数据科学分析工作流。
  • 微服务与云原生工具构建：推荐使用 HugeGraph Go Client 或直接调用 RESTful API。
  • 终端离线调试或临时查询：推荐使用 Gremlin Console。

1 - HugeGraph Java Client

1 HugeGraph-Client 概述

HugeGraph Java Client 将 Java API 转换为 HugeGraph Server 的 REST 请求，支持管理 Schema 和图数据、执行 Gremlin 及调用 Traverser API。本文涵盖 Java 项目的快速接入示例与全量核心 API 参考。

其他语言可使用 Go Client 或 Python Client。

2 环境要求

  • JDK 17，用于本文示例及从 Toolchain master 构建 Client 1.8.0
  • Maven 3.6.3+

3 使用流程

按下面的顺序接入 HugeGraph-Client。

  1. 使用 IntelliJ IDEA 或 Eclipse 新建 Maven 工程。
  2. 在 pom.xml 中添加 HugeGraph-Client 依赖。
  3. 创建客户端、调用 API，并在使用后关闭客户端。

5 HugeClient 构造与操作入口

HugeGraph-Client 是操作 graph 的总入口，用户必须先创建出 HugeGraph-Client 对象，与 HugeGraph-Server 建立连接（伪连接）后，才能获取到 schema、graph 以及 gremlin 的操作入口对象。

HugeGraph-Client 连接服务端已有的图。构造器支持传入 GraphSpace；使用双参数构造器或传入空值时，GraphSpace 默认为 DEFAULT。

      • 单个属性，支持相等查询，比如：person 顶点的 city 属性的二级索引，可以用g.V().has("city", "北京") 查询"city 属性值是北京"的全部顶点

    • Range 支持数值类型的范围查询
      • 必须是单个数字或者日期属性，比如：person 顶点的 age 属性的范围索引，可以用g.V().has("age", P.gt(18)) 查询"age属性值大于18"的顶点。除了P.gt()以外，还支持P.gte(), P.lte(), P.lt(), P.eq(), P.between(), P.inside()和P.outside()等

      • shard index 只有单个数字或者日期属性时，等价于 range index

7 图数据操作 (GraphManager)

7.1 Vertex

顶点是构成图的最基本元素，一个图中可以有非常多的顶点。下面给出一个添加顶点的例子：

1Vertex marko = graph.addVertex(T.LABEL, "person", "name", "marko", "age", 29);
2Vertex lop = graph.addVertex(T.LABEL, "software", "name", "lop", "lang", "java", "price", 328);
  • 添加顶点的关键是顶点属性，添加顶点函数的参数个数必须为偶数，且满足key1 -> val1, key2 -> val2 ···的顺序排列，键值对之间的顺序是自由的。
  • 参数中必须包含一对特殊的键值对，就是T.LABEL -> "val"，用来定义该顶点的类别，以便于程序从缓存或后端获取到该 VertexLabel 的 schema 定义，然后做后续的约束检查。例子中的 label 定义为 person。T.LABEL 就是常量 "label"，直接传入该字符串效果相同。
  • 如果顶点类型的 Id 策略为 AUTOMATIC，则不允许用户传入 id 键值对。
  • 如果顶点类型的 Id 策略为 CUSTOMIZE_STRING，则用户需要自己传入 String 类型 id 的值，键值对形如：T.ID, "123456"。
  • 如果顶点类型的 Id 策略为 CUSTOMIZE_NUMBER，则用户需要自己传入 Number 类型 id 的值，键值对形如：T.ID, 123456。
  • 如果顶点类型的 Id 策略为 PRIMARY_KEY，参数还必须全部包含该primaryKeys对应属性的名和值，如果不设置会抛出异常。比如之前person的primaryKeys是name，例子中就设置了name的值为marko。
  • 对于非 nullableKeys 的属性，必须要赋值。
  • 剩下的参数就是顶点其他属性的设置，但并非必须。
  • 调用addVertex方法后，顶点会立刻被插入到后端存储系统中。

7.2 Edge

有了点，还需要边才能构成完整的图。下面给出一个添加边的例子：

1Edge knows1 = marko.addEdge("knows", vadas, "city", "Beijing");
  • 由（源）顶点来调用添加边的函数，函数第一个参数为边的 label，第二个参数是目标顶点，这两个参数的位置和顺序是固定的。后续的参数就是key1 -> val1, key2 -> val2 ···的顺序排列，设置边的属性，键值对顺序自由。
  • 源顶点和目标顶点必须符合 EdgeLabel 中 source-label 和 target-label 的定义，不能随意添加。
  • 对于非 nullableKeys 的属性，必须要赋值。

注意：当 frequency 为 multiple 时必须要设置 sortKeys 对应属性类型的值。

服务端版本与 GraphSpace 路由

客户端在初始化阶段自动解析 GraphSpace 路由：

  • 显式传入非空 graphspace 时，直接启用对应的 GraphSpace 路由模式。
  • graphspace=None 时，客户端向 GET {url}/versions 发起探测以获取服务端内核版本。
  • HugeGraph Server 1.7+ 默认启用 GraphSpace 并分配至 DEFAULT。
  • HugeGraph Server 1.5 / 1.6 保持传统无 GraphSpace 路由。
  • 低于 1.5.0 的版本不支持，初始化时会抛出 RuntimeError。
  • 若版本探测失败且未显式指定 GraphSpace，客户端初始化将直接抛出异常，避免错误猜测服务端路由结构。

路由模式决定了服务端请求路径前缀：开启 GraphSpace 时为 /graphspaces/<graphspace>/graphs/<graph>/...，关闭时为 /graphs/<graph>/...。

方法命名规范与迁移说明

  • 推荐规范：新代码请统一使用 snake_case 方法名（如 add_vertex、property_key 等）。
  • 兼容保证：现有的公开 CamelCase 方法（如 addVertex、propertyKey 等）作为直接别名持续得到兼容支持。
  • 客户端生命周期：结束调用后请统一通过 client.close() 释放连接池会话资源，无需单独关闭单个 manager。
  • 返回契约：
    • 传统快捷接口 get_all_graphs()、get_version() 和 get_graph_info() 保持返回 JSON 字符串以维护向前兼容。
    • 标准现代接口 client.graphs().list()、client.version().version() 和 client.graphs().get(graph_name) 直接返回已解析的 Python 字典。
    • 带权最短路径与单源最短路径方法不再支持 max_depth 参数（服务端接口不支持）；请使用 capacity、max_degree 和 skip_degree 参数进行限制。

3 - HugeGraph Go 客户端快速入门

HugeGraph Go Client 是 Toolchain 仓库中的 Go SDK，目前提供版本查询、Schema（PropertyKey、VertexLabel、EdgeLabel）、顶点和 Gremlin API。边数据 API 尚未实现。

该模块仍在开发中。接口范围以 hugegraph-client-go/api/v1 下的源码为准。

环境要求

  • Go 1.19 或更高版本
  • 可访问的 HugeGraph Server，默认示例地址为 http://127.0.0.1:8080

安装

在 Go module 项目中执行：

1go get github.com/apache/hugegraph-toolchain/hugegraph-client-go

初始化客户端

NewCommonClient 要求 Host 是 IP 地址，Port 在 1 到 65535 之间；客户端始终使用明文 HTTP 连接。未启用认证时，用户名和密码留空；只有两者都设置时才会发送 Basic Auth。

入口用途

Schema()查询完整 Schema

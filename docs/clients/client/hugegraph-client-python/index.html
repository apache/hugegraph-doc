HugeGraph Python Client Quick Start

hugegraph-python-client is the Python SDK for Apache HugeGraph. It provides schema management, graph data manipulation, Gremlin execution, real-time traversals, and asynchronous whole-graph computing. HugeGraph-LLM and HugeGraph-ML also use this client for database operations.

The client source code is hosted in the hugegraph-ai repository under hugegraph-python-client/. The import package name is pyhugegraph.

Requirements

  • Python >= 3.12 (Python 3.12–3.14 supported).
  • HugeGraph Server 1.5.0 or later (Server 1.7+ recommends GraphSpace mode; 1.5/1.6 uses legacy routing).
  • pip or uv package manager.

Runtime dependencies include decorator, requests, urllib3, and rich.

Installation

The client provides two installation methods depending on whether you require the stable PyPI release or development features from the master branch.

Note

Version & Feature Boundary: The published PyPI release (hugegraph-python 1.7.x) provides the baseline client supporting CamelCase methods with legacy snake_case aliases. The modern features demonstrated in this guide — including native snake_case APIs, client.olap() whole-graph algorithms, client.task().wait(), client.close(), and updated traverser signatures — align with the master development branch. For testing these features, install the client from source.

PyPI (Stable 1.7.x)
1pip install hugegraph-python
2# Or using uv:
3# uv pip install hugegraph-python
Source (Master)
1git clone https://github.com/apache/hugegraph-ai.git
2cd hugegraph-ai/hugegraph-python-client
3pip install -e .
Workspace (uv)
1git clone https://github.com/apache/hugegraph-ai.git
2cd hugegraph-ai
3uv sync --extra python-client
4source .venv/bin/activate

Client Parameters

PyHugeClient(url, graph, user, pwd, graphspace=None, timeout=None, *, token=None)

ParameterTypeDefaultDescription
urlstrrequiredBase URL of HugeGraph Server. Prepends http:// if no scheme is provided (e.g. 127.0.0.1:8080).
graphstrrequiredTarget graph name. Second positional parameter.
userstrrequiredUsername sent via HTTP Basic Auth.
pwdstrrequiredPassword sent via HTTP Basic Auth.
graphspacestr or NoneNoneGraphSpace name. When None, resolved automatically via version probe.
timeoutfloat, tuple[float, float] or NoneNone(connect, read) timeouts in seconds, or a single float for both. Defaults to (0.5, 15.0).
tokenstr or NoneNoneExplicit Bearer token; overrides Basic Auth when provided.

Idempotent requests retry on 500, 502, and 504 responses up to three times with a 0.1 backoff factor. Task waiting automatically manages its polling budget without extra HTTP retries.

Server Version and GraphSpace

The client resolves GraphSpace routing at initialization:

  • When an explicit graphspace string is passed, GraphSpace routing is activated immediately.
  • When graphspace=None, the client checks GET {url}/versions to determine the server core version.
  • HugeGraph Server 1.7+ defaults to GraphSpace DEFAULT.
  • HugeGraph Server 1.5 / 1.6 uses legacy non-GraphSpace routing.
  • Servers prior to 1.5.0 are not supported and raise RuntimeError.
  • If the version probe fails and no GraphSpace was specified, client initialization raises an error rather than assuming an invalid route layout.

The routing mode determines request path prefixes: /graphspaces/<graphspace>/graphs/<graph>/... when GraphSpace is enabled, or /graphs/<graph>/... when disabled.

Common Operations

Build the Schema

Schema builders are fluent. Call create() to apply, or use append(), eliminate(), and remove() to update existing definitions:

 1schema = client.schema()
 2
 3# Property keys: as_text / as_int / as_long / as_float / as_double / as_bool / as_date
 4# Cardinality: value_single / value_list / value_set
 5schema.property_key("age").as_int().value_single().if_not_exist().create()
 6
 7# Vertex labels: use_automatic_id / use_customize_string_id / use_primary_key_id
 8schema.vertex_label("person").properties("name", "age", "city") \
 9      .primary_keys("name").nullable_keys("city").if_not_exist().create()
10
11# Edge labels: link() specifies source and target vertex labels
12schema.edge_label("knows").link("person", "person").multi_times() \
13      .properties("date", "city").sort_keys("date").nullable_keys("city") \
14      .if_not_exist().create()
15
16# Index labels: on_v / on_e, secondary / range / search / shard / unique
17schema.index_label("personByCity").on_v("person").by("city") \
18      .secondary().if_not_exist().create()

Read, Update, and Delete Graph Data

The graph API accepts property dictionaries:

1graph = client.graph()
2graph.append_vertex(person.id, {"birthDate": "1940-04-25"})    # Append properties
3graph.eliminate_vertex(person.id, {"birthDate": "1940-04-25"}) # Drop properties
4graph.append_edge(edge.id, {"city": "Beijing"})
5graph.eliminate_edge(edge.id, {"city": "Beijing"})
6graph.remove_edge_by_id(edge.id)
7graph.remove_vertex_by_id(person.id)

add_vertex returns a VertexData instance containing id, label, type, and properties. add_edge returns an EdgeData instance containing id, label, type, outV, outVLabel, inV, inVLabel, and properties.

Vertex IDs passed to the client may be strings, integers, or uuid.UUID objects. Booleans are rejected, and integer values must fall within the 64-bit signed range.

Batch Writes

add_vertices accepts (label, properties) tuples, and add_edges accepts (label, out_id, in_id, out_label, in_label, properties) tuples:

1graph = client.graph()
2vertices = graph.add_vertices([
3    ("person", {"name": "Alice", "age": 20}),
4    ("person", {"name": "Bob", "age": 23}),
5])
6edges = graph.add_edges([
7    ("knows", vertices[0].id, vertices[1].id, "person", "person", {"date": "2012-01-10"}),
8])

Traverse the Graph (OLTP)

client.traverser() wraps the server’s real-time traverser endpoints for neighborhood, path, and similarity queries:

 1traverser = client.traverser()
 2
 3traverser.k_out(marko_id, 2)
 4traverser.k_neighbor(marko_id, 2)
 5traverser.same_neighbors(marko_id, josh_id)
 6traverser.jaccard_similarity(marko_id, josh_id)
 7traverser.shortest_path(marko_id, ripple_id, 3)
 8traverser.all_shortest_paths(marko_id, ripple_id, 3)
 9traverser.weighted_shortest_path(marko_id, ripple_id, "weight", 3)
10traverser.single_source_shortest_path(marko_id, 2)
11traverser.multi_node_shortest_path([marko_id, josh_id], max_depth=2)
12traverser.paths(marko_id, josh_id, 2)
13traverser.crosspoints(marko_id, josh_id, 2)
14traverser.rings(marko_id, 3)
15traverser.rays(marko_id, 2)
16traverser.vertices(marko_id)
17traverser.edges(edge_id)

The POST-based variants accept complex request bodies: advanced_paths, customized_paths, template_paths, customized_crosspoints, and fusiform_similarity.

OLAP Whole-Graph Computing

For heavy full-graph algorithms (such as PageRank, Louvain, or Centrality), use client.olap(). These jobs run asynchronously on the server and are tracked through task IDs:

 1# 1. Submit an asynchronous computation task
 2receipt = client.olap().count_vertex()
 3task_id = receipt["task_id"]
 4
 5# 2. Wait for completion and retrieve results
 6task = client.task().wait(task_id, timeout=300, poll_interval=1)
 7result = client.task().result(task)
 8print(result)
 9
10# Or combine submit, wait, and decode in one step:
11result = client.olap().run("count_vertex", timeout=60)

Supported OLAP Algorithms

The server provides 17 unique whole-graph algorithm endpoints:

CategoryAlgorithm Names
Statisticscount_edge, count_vertex, subgraph_stat, triangle_count, rings
Centralitybetweenness_centrality, closeness_centrality, degree_centrality, eigenvector_centrality, stress_centrality
Community & Clusteringcluster_coefficient, k_core, louvain, lpa, weak_connected_component
Ranking & Similaritypage_rank, fusiform_similarity
Tip

Algorithms like page_rank write calculated rank properties back to the graph. For graphs requiring strict schema definitions, declare a nullable DOUBLE property named r_rank on participating vertex labels prior to execution.

Task Lifecycle Management

The TaskManager provides control over asynchronous jobs:

 1task = client.task()
 2
 3# List recent tasks
 4task.list_tasks(status="success", limit=10)
 5
 6# Poll and wait for a task to complete
 7record = task.wait(task_id, timeout=300, poll_interval=1)
 8
 9# Decode task results (parses JSON response once)
10result = task.result(record)
11
12# Cancel or delete tasks
13task.cancel_task(task_id)
14task.delete_task(task_id, force=False)
  • wait(id, timeout=300, poll_interval=1) polls status without fetching the full result payload on every tick.
  • TaskTimeoutError indicates client-side polling timed out; the background job on the server continues running.
  • To terminate a running server task, invoke cancel_task(id) explicitly.

Method Naming and Migration

  • Preferred style: New code should use snake_case methods (add_vertex, property_key, etc.).
  • Backward compatibility: Existing public CamelCase methods (addVertex, propertyKey, etc.) remain supported as direct aliases.
  • Client lifecycle: Use client.close() to release connection pool resources rather than closing individual managers.
  • Return contracts:
    • Legacy convenience helpers get_all_graphs(), get_version(), and get_graph_info() retain JSON strings for backwards compatibility.
    • Modern accessors client.graphs().list(), client.version().version(), and client.graphs().get(graph_name) return parsed Python dictionaries.
    • Weighted and single-source shortest path methods no longer accept max_depth (unsupported by the server endpoint); use capacity, max_degree, and skip_degree controls instead.

Error Handling

Exceptions reside in pyhugegraph.utils.exceptions:

ExceptionRaised when
NotAuthorizedErrorServer responds with HTTP 401
NotFoundErrorServer responds with HTTP 404
ServerErrorNon-2xx server response (attaches server error payload)
ResponseParseErrorResponse body cannot be decoded to the expected structure
ServiceUnavailableErrorServer is temporarily unavailable
InvalidParameterError, CreateError, RemoveError, UpdateError, DataFormatErrorRaised on client-side validation failures

Sensitive fields (passwords, tokens, secrets) are masked automatically in logs.

1from pyhugegraph.utils.exceptions import NotFoundError
2
3try:
4    graph.get_vertex_by_id("missing-id")
5except NotFoundError:
6    print("Vertex not found")

Development and Verification

Run code quality and test suites from the root of the HugeGraph-AI repository:

  1. Format and lint checks:

    1uv run --extra dev ruff format --check .
2uv run --extra dev ruff check .
3uv run --extra dev ty check hugegraph-python-client/src/pyhugegraph

  2. Run unit and contract tests:

    1uv run pytest hugegraph-python-client/src/tests -m "unit or contract"

  3. Run integration tests against a HugeGraph Server:

    1HUGEGRAPH_URL=http://127.0.0.1:8080 \
2HUGEGRAPH_GRAPH=hugegraph \
3HUGEGRAPH_USER=admin \
4HUGEGRAPH_PASSWORD=admin \
5uv run pytest hugegraph-python-client/src/tests -m "integration and hugegraph"

Upstream CI validates against hugegraph/hugegraph:latest and regression tests against 1.7.0. Source code and test suites reside in hugegraph-python-client/src/pyhugegraph/ and hugegraph-python-client/src/tests/.
